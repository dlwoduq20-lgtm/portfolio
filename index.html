현업에서는 크게 신경 쓰지 않던 단순 팝업이었으나, GA 데이터를 직접 뜯어보니 사용자들이 의외로 상품을 찾을 때 이 메뉴를 굉장히 많이 쓰고 있음을 발견했습니다.

  • 수많은 ETF 중에서 원하는 종목을 빠르게 좁혀볼 수 있도록 해외/국내 탭과 개인연금·퇴직연금 전용 필터 신규 추가
  • 가나다순 정렬과 지수·테마·섹터별 직관적인 분류 구성을 적용하여 탐색 편의성을 대폭 개선하고 정식 배포 완료
범위 통제 & 일정 관리

제한된 일정과 리소스 속, 현업과 ‘업무 가능 범위’를 조율하여 완수

5개 사이트를 총괄 운영하다 보면 각 부서에서 요청하는 개발 건이 계속해서 쌓이고, 작업 도중에도 신규 건이나 당일 처리가 필요한 급건이 수시로 발생했습니다.

  • 일정과 리소스가 한정된 상황에서 모든 요구사항을 무조건 떠안지 않고, 비즈니스 시급성과 개발 공수를 종합적으로 판단하여 현업과 ‘이번 일정에 실제 구현 가능한 업무 범위’를 현실적으로 조절
  • 급건이 들어올 때마다 현업과 소통하여 우선순위를 다시 정리하고 스코프를 명확히 통제함으로써, 개발팀의 과부하를 막고 주요 기능 배포 일정을 차질 없이 지켜냄
제안 방식

매달 1건씩 제안, 운영 부담을 줄여 채택 유도

개선안은 모두 제안 문서로 만들어 현업과 논의했습니다. 운영 인력이 부족해 반대할 때는, 손이 덜 가도록 시스템 자동화 방식을 보완해 다시 제안하며 채택을 이끌어냈습니다. GA4를 보며 얻은 사용자 반응 인사이트도 정기적으로 보고했습니다.

주문 흐름 개선 제안

어디서 시작해도 자연스럽게 이어지는 5가지 주문 흐름 설계

사용자는 특정 메뉴를 먹고 싶어 들어오기도 하고, 메인의 추천 메뉴를 보고 들어오거나, 단골 매장에서 빠르게 재주문하기도 합니다. 메뉴를 먼저 고르든 배달 매장을 먼저 찾든, 어디서 시작하더라도 중간에 막힘없이 옵션 선택과 장바구니로 이어지도록 주문 경로를 설계했습니다.

CASE 1주문 유형부터
주문 유형→주소→브랜드/매장→메뉴
CASE 2매장부터
매장→주소→주문 유형→메뉴
CASE 3메뉴부터
메뉴→주소→주문 유형→매장
CASE 4메인 큐레이션
주소→주문 유형→브랜드/매장→메뉴
CASE 5단골 재주문
주소→주문 유형→매장→메뉴
운영팀 설득

“경로가 늘어나면 테스트가 어렵다”는 우려를 상세 시나리오로 해소

운영팀은 주문 경로가 여러 갈래로 나뉘면 테스트할 것도 많아지고 오류가 날까 봐 크게 걱정했습니다. 각 경로별로 화면이 어떻게 바뀌고 예외 상황에서 어떻게 처리되는지 꼼꼼하게 시나리오를 만들어 운영팀을 안심시키고 설득했습니다.

추천 & 어드민 설계

자연스러운 연관 메뉴 추천과 운영자가 직접 관리하는 어드민 옵션 구조

  • 최근 주문 메뉴: 자주 시켜 먹는 단골 고객이 많은 프랜차이즈 특성을 반영해 최근 주문 메뉴를 우선 노출
  • 연관 메뉴 추천: 함께 먹기 좋은 사이드 메뉴나 같은 라인업 메뉴를 제안해 주문 금액과 만족도 향상 유도
  • 어드민 옵션 관리 기능: 용기 포장이나 갈기 정도처럼 정해진 옵션만 쓰던 방식을 바꿨습니다. 앞으로 새 브랜드나 신메뉴가 나오더라도 개발자 손을 거치지 않고, 운영자가 어드민에서 직접 옵션을 만들고 수정할 수 있도록 구조를 잡았습니다.
팀 리딩

핵심 주문 직접 완수 & 창업 파트 품질 견인

  • 촉박한 일정에 따른 실무진의 피로를 관리하기 위해 회사에 인력 지원을 요청하고 진척 상황을 투명하게 공유하며 런칭 완수

API 해석 및 설계

문서 없는 통신 3사 API를 직접 테스트·해석하여 가입 서비스로 연결

통신사 개통 API는 단계별 데이터 정합성이 엄격했습니다. 남아있는 명세서가 없어 개발팀과 함께 통신 3사 API를 케이스별로 전수 호출·테스트했습니다. 수많은 에러 코드와 응답 데이터를 하나하나 분석해 필요한 데이터 규격을 파악하고, 이를 고객이 화면에서 막힘없이 입력할 수 있는 단계별 가입 서비스로 역설계했습니다.

상담 문의 줄이기

통신 3사 API 지원 범위를 전수 분석해 셀프 처리 기능 확대

개통 취소, 요금제 변경, 부가서비스 신청/해지 등 고객센터 문의가 잦은 기능들을 정리했습니다. 통신 3사에서 즉시 처리 API를 지원하는 기능은 고객이 홈페이지에서 직접 완결할 수 있도록 서비스 화면을 구축하고, 지원하지 않는 업무는 온라인 간편 접수로 연결하여 상담 통화량을 대폭 줄였습니다.

API 해석 및 서비스 연결

제휴사 충전 API 명세를 해석하여 운전자 중심의 화면으로 연결

기술 API 명세서에 정의된 충전기 상태값(대기/충전중/고장), 잔여 전력량, 과금 데이터 흐름을 면밀히 분석하고 해석했습니다. 복잡한 개발 스펙을 운전자의 실제 이용 흐름에 맞춰, 지도에서 아우디 충전소를 필터링하고 실시간 충전 가능 상태 확인, 예약, 결제까지 한 번에 끝낼 수 있는 직관적인 서비스 UI로 풀어냈습니다.

제휴사 충전 API 해석→운전자 충전 동선 기획→충전 카드 및 결제 API 연동→전시장 실차 테스트
현장 실차 테스트

사무실에서 기획서만 보지 않고 아우디 전시장을 직접 찾아갔습니다. 실제 e-트론 차량에 충전기를 꽂아보며, 통신 지연으로 화면이 멈추거나 충전이 중간에 끊기는 문제, 카드 포인트 차감 오류 등 현장에서 생길 수 있는 온갖 예외 상황을 꼼꼼하게 테스트하고 수정했습니다.

매드포갈릭 태블릿오더 구축

손님이 매장 테이블에서 태블릿으로 주문하면 포스(POS)로 자동 접수되는 주문 시스템과 함께, 매장 직원용 모드 및 프랜차이즈 관리자(어드민) 기능을 설계했습니다.

01

비즈니스 배경 및 요구사항

테이블 태블릿에서 손님이 편하게 주문하고, 주문 내역이 매장 포스(POS)에 오차 없이 즉시 연동되도록 구축.

바쁜 매장에서 점주와 직원이 손쉽게 다룰 수 있어야 했고, 새 매장을 열 때 수많은 메뉴 데이터를 일일이 다시 입력하지 않고 한 번에 세팅할 수 있는 기능이 필요했습니다.

내가 한 일

POS 데이터 연동

POS 데이터를 해석하여 고화질 태블릿 주문 서비스로 연결

매장 포스(POS)에 등록된 원천 상품 및 주문 데이터를 마스터로 삼아, 고객 태블릿 화면에 실시간으로 연결하는 데이터 구조를 설계했습니다. 단순 가격 정보에 머물던 포스 데이터를 어드민에서 고화질 사진, 추천 세트, 굽기 옵션 등과 결합하여 먹음직스럽고 편리한 고객 주문 경험으로 서비스화했습니다.

POS 마스터 데이터→어드민 — 사진/옵션 추가 가공→손님용 태블릿 화면직원 전용 매장 관리 모드
화면 모드 분리

손님용 주문 화면과 직원 전용 매장 관리 화면 분리

손님에게는 브랜드 분위기를 살린 깔끔한 메뉴판을 보여주고, 매장 직원에게는 특정 터치 동작(히든 제스처)으로 열리는 관리자 모드를 제공했습니다. 직원이 손님 태블릿에서 바로 테이블 상태를 확인하고, 품절 메뉴를 숨기거나 직원을 호출할 수 있도록 설계했습니다.

운영 편의 기능

새 매장이 생겨도 한 번에 세팅하는 '데이터 복사' 기능 설계

매드포갈릭처럼 매장이 늘어날 때마다 수많은 메뉴와 옵션을 처음부터 다시 등록하는 건 엄청난 비효율이었습니다. 기존 매장의 메뉴판 설정을 그대로 가져오는 '매장 복사 / 메뉴 복사 / 브랜드 복사' 기능을 기획했습니다. 복사할 데이터의 갈래가 워낙 방대해서, 메뉴나 옵션이 하나라도 누락되지 않도록 경우의 수를 꼼꼼하게 따져가며 검증했습니다.
